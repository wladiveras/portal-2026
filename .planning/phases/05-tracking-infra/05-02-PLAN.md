<objective>
Build the tracking runtime: a client plugin that captures visitor metadata + UTM + events, and two Nitro endpoints that proxy into Supabase using the service role (which must never reach the browser bundle).
</objective>

<interfaces>
Client: `useTracker().trackEvent({ type: 'click_whatsapp', target, meta })`.
Server: `POST /api/track/event` body: `{ anonId, type, target?, path?, meta?, utm? }` → 204.
Server: `POST /api/track/lead` body: `{ anonId, source, displayName?, contactValue?, utm? }` → `{ leadId }`.

Use `server/utils/supabase.ts` to expose `serverSupabaseServiceRole()` wrapping `createClient(url, serviceKey)` with `persistSession: false`.
</interfaces>

<tasks>
- `app/utils/utm.ts`: parse `window.location.search` into `{ utm_source, utm_medium, utm_campaign, utm_content, utm_term }`. Unit test.
- `app/composables/useTracker.ts`: manages `anon_id` cookie, exposes `trackEvent` and `trackLead`. Uses `$fetch('/api/track/...')`.
- `app/plugins/tracker.client.ts`: on navigation (`app:mounted` + `nuxt-link:click`) emits `page_view`; pushes an initial `visitor upsert` that the server can dedupe.
- `server/utils/supabase.ts`: `serverSupabaseServiceRole(event)` (returns typed client).
- `server/api/track/event.post.ts`: validate, upsert visitor (`anon_id`), insert into `lead_events`.
- `server/api/track/lead.post.ts`: validate, upsert visitor, insert `leads`, link current event ids when possible.
- Tests: utm parser unit; payload validator unit.
</tasks>

<threat_model>
- Service role exfiltration: keep it out of `runtimeConfig.public`; only in `runtimeConfig.supabaseServiceKey`.
- Spam: rate-limit per `anonId` in memory (simple leaky bucket) or by IP using `event.node.req.socket.remoteAddress` bucket of 60 req/min.
- PII: never log raw IP; hash with HMAC if needed for geo later.
</threat_model>

<verification>
`npm run test` passes new specs. E2E smoke: `page.route('**/api/track/event', route => route.fulfill({status:204}))` asserting at least one call on landing load.
</verification>
